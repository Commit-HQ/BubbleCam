# Architecture

One SvelteKit application, prerendered whole to static files, which Cloudflare serves as a Worker's static assets with no code of ours running there. Everything that happens, happens in the browser: the camera, the pictures, the cartoons kept on the device, and the video made from them. Use strict TypeScript and Svelte 5 runes. Why it behaves as it does is in the [decisions](decisions.md).

## Pages and languages

Pages live in two route groups. `(site)` holds the privacy page and the 404 pages: static HTML without client-side JavaScript (`csr = false` in its `+layout.ts`). BubbleCam's landing page is on Commit's site, at bubbleboard.fyi/apps/bubblecam ([ADR 0001](adr/0001-an-origin-of-its-own.md)). `(app)` holds the app, which is the site's home: the cartoons' page (`/`) and the studio (`/film`), prerendered as shells that then run in the browser. Their HTML holds only what the first paint needs; the cartoons are read from IndexedDB in the browser. The root layout adds the stylesheet, the icons, and the document's language.

Croatian is served at `/` and `/film`, English at `/en` and `/en/film`: the optional `[[locale=locale]]` segment and its matcher in `src/params.ts` keep the default language unprefixed, and `src/lib/paths.ts` builds every path. The app's language is chosen in its settings, and the privacy page's with a switch in its header. The studio is prerendered once, so the cartoon it opens travels in the query (`/film?id=…`), which the page reads in the browser; without one, the first picture starts a new cartoon, and the address then names it, by a shallow navigation that replaces the history entry. Either way the language is in the address, so no cookie is needed. All interface copy lives in `src/lib/i18n/en.ts` and `hr.ts`, which have the same shape; copy that names or counts something is a function, so each language builds its own sentence and plural (`Intl.PluralRules`). The privacy page addresses parents and teachers formally ("vi"), and the app talks to children ("ti").

Canonical URLs, `hreflang` alternates, and link previews need an absolute address, which prerendered pages can't take from a request. It comes from `PUBLIC_SITE_URL`, a static public variable that `src/env.ts` declares and checks at build time, imported from `$app/env/public`; `src/lib/project.ts` builds absolute links with it. Each language has a web app manifest, prerendered from `src/routes/(app)/[[locale=locale]]/manifest.webmanifest/+server.ts`, with the same `id` and scope, so installing from either language gives one app.

`src/hooks.server.ts` runs only while pages are prerendered: it writes the document's language and decides which fonts each page preloads.

## The studio

The studio's code is in `src/lib/studio`, and its screens in `src/lib/app`. `studio.svelte.ts` holds the state: the cartoon, its pictures, what the viewfinder shows (the camera, a picture taken earlier, or the cartoon playing), and the camera. The modules around it each do one thing:

- `settings.ts` holds what a grown-up set, kept in `localStorage`: the shape of new cartoons, whether the screen may turn, the shutter's rest, the sounds, whether deleting a cartoon and making a video are guarded, the quality of pictures and of videos, whether the studio has its advanced tools, and how easily a clap is heard. What belongs to those tools alone (the ghost's strength, the grid, the self-timer, how often a video repeats) counts only while they're on. Anything missing or not understood is the default. The studio reads them once, as it opens.
- `camera.ts` opens the camera, asking for 720p or the size the pictures' quality asks for, and names what went wrong when it can't (not allowed, not there, busy, not in this browser). When the Permissions API says the browser is about to ask the person, the microphone is asked for in the same request, and its track is stopped at once; if that request fails, the camera is asked for alone. For the shutter that listens for a clap it opens the camera and the microphone in one request and keeps both.
- `voice.ts` records a cartoon's sounds with `MediaRecorder`, in whatever sound file the browser writes (WebM with Opus, or MP4 with AAC in Safari), decodes one into samples for a video, and mixes several into one row of samples (`mixSamples`), each times its loudness, clamped. `Studio.record` takes the layer to record (`voice`, `ambience`, or `music`), stops the camera, opens the microphone, with the browser's noise suppression and echo cancelling only for a voice, counts down, and plays the cartoon through once (`Player`'s `once`) without its other sounds; the recorder starts with the first picture and ends with the last.
- `geometry.ts` decides a cartoon's size and the part of the camera's picture it keeps. A cartoon takes the shape of the camera's picture at its first picture, or that shape turned on its side when a grown-up chose that cartoons lie or stand, at most 1280 pixels long with both sides a multiple of 16, which every video encoder takes. Later pictures keep the middle of the camera's picture in that shape, which is exactly what the viewfinder shows (`object-fit: cover`), so the ghost lines up. Zoomed in, the viewfinder scales the camera's picture and a picture keeps the middle that's still in view.
- `shutter.ts` takes a picture. The tap only draws the camera's current picture at the cartoon's size, and onto the ghost's canvas, which the GPU does in a moment. The drawing goes to a worker as a transferred bitmap (`encode.worker.ts`), which encodes it as a JPEG at quality 0.9 and a 144-pixel-tall thumbnail at 0.8, off the page. After a press the big button rests, for 0.8 seconds unless a grown-up set otherwise, during which presses are ignored and, after a picture, the button's red grows back. With the self-timer, the press starts a countdown in `Studio` instead, one timeout a second, which ends in the same picture, and starts again where that's asked; a second press, a picture being looked at, the cartoon playing, or the camera stopping ends it. Browsers without canvases in workers, such as Safari before 16.4, and pages where the worker can't start, encode on the page with `toBlob`; a picture a failed worker lost leaves the strip.
- `stillness.ts` presses the shutter when the picture has settled. Ten times a second `Studio` draws the part of the camera's picture that a picture keeps onto a canvas 64 pixels long and makes it grey (`Eye`); `Stillness` counts the pixels that differ from the look before and from the look at the last picture, calls it a move when 1.5 % of them do, and asks for a picture once fewer than 0.4 % have differed between looks for a second. It starts over with every picture, however taken, and whenever the camera isn't what's on screen.
- `clap.ts` presses the shutter at a clap. `Ear` connects the microphone to two Web Audio analysers that play nothing back: one behind a 1500 Hz high-pass, read fifty times a second for the loudest instant of the last moment, and one behind a 200 Hz high-pass that holds the last third of a second. `Claps` follows the room's usual loudness and, when a sound stands out from it, waits 140 ms and weighs that third of a second in stretches of 5 ms (`clapLike`): little before the loudest instant, less soon after it, and little left 60 ms on. `Studio` opens the camera again together with the microphone for it, since a phone doesn't always keep both going when they're opened one after the other, takes the picture 450 ms after the clap, and listens to nothing while its own click sounds.
- `films.ts` keeps the cartoons in IndexedDB: a `films` store of records, each naming its pictures in order, and `images` and `thumbs` stores of JPEG blobs by picture ID, so opening a cartoon reads only its thumbnails. The cartoons' page reads each cartoon's first picture full size for its card. Moving a picture rewrites only the order in the cartoon's record, and a picture held on screen is a number of seconds by its ID in the record's `holds`, which most cartoons don't have. A cartoon's sounds are `Blob`s in its record, `voice`, `ambience`, and `music`: the browser keeps such a file beside the record and reads it only when it's played, and the database needed no new version for them. How loud each plays is a number from 0 to 1 by its layer in the record's `volumes`, kept only when it isn't 1.
- `timeline.ts` turns a cartoon into the turns it's shown in: each picture once, a held one for as many more turns as its seconds take at the cartoon's speed, and the whole as many times over as a video repeats. The video and the cards' previews follow it. Every change is one transaction, so a cartoon never names a picture it doesn't have. A cartoon left without pictures disappears from the list, and is deleted once it hasn't changed for a minute.
- `player.ts` plays a cartoon on a canvas over the camera, decoding ten pictures ahead and letting them go once shown; a cartoon of ten pictures or fewer stays decoded and loops without decoding again. A picture that isn't decoded in time keeps the one before on screen a little longer, and a held one stays for its seconds. The cartoon's sounds, each decoded once, start over together through Web Audio each time the first picture shows.
- `video.ts` and `video.worker.ts` make the video. The worker reads each picture from IndexedDB, draws it on an `OffscreenCanvas`, and encodes it with WebCodecs at the cartoon's own frame rate, a held picture once for each of its turns, with the sounds' samples, which the page decodes, mixes, and hands over, encoded beside them up to the picture just added, while Mediabunny writes the MP4 (H.264), or WebM (VP9 or VP8) where H.264 can't be encoded; it runs faster than the cartoon plays. Without WebCodecs in workers, or where the browser can encode the sound as neither AAC nor Opus, the page plays the cartoon on the dialog's canvas once and records it with `MediaRecorder`, in real time, with the sounds played into the recording, each through its own gain.
- `sound.ts` makes the shutter's click, the bubble's pop, and the self-timer's tick with Web Audio, from noise and tones, unless a grown-up turned the sounds off, and buzzes phones that can. It plays a cartoon's sounds through the same audio context, which a tap has already started, each through a gain node that a slider turns while it plays, and tells Safari's audio session to listen while a voice is recorded or a clap is listened for.
- `rotation.ts` keeps the screen from turning, with the Screen Orientation API, where a grown-up asked for it and the browser can: Chromium on Android, for an installed app as it is, and for a tab only while it's full screen, which the first tap in the studio starts. The screen is kept as the cartoon lies or stands.

The settings' dialog is `src/lib/app/SettingsDialog.svelte`, opened from the cog in the cartoons' page's header. It first asks a sum (`Gate.svelte`, with the sum itself in `gate.ts`), then shows the settings and keeps every change at once. The language is one of them: choosing it goes to the same page in that language (`goto`, replacing the history entry), where the dialog stays open, since both languages are one route. Where deleting is guarded, the question that deletes a cartoon (`ConfirmDialog.svelte`) asks the same sum first, and where making a video is, the sum comes in a dialog of its own (`GateDialog.svelte`) before the video's. With the advanced tools on, `FrameStrip.svelte` lets a picture be dragged to another place: places are worked out from the strip's layout, not from where the pictures are drawn, since they slide while they change places; a touch drag starts after the finger has rested 350 ms, and a `touchmove` listener that isn't passive keeps the strip from scrolling under it.

Pictures show in the strip and the ghost the moment they're taken, and are written a moment later. Every change to the device's cartoons goes through one queue in `Studio` (`#write`), so changes happen in the order they were made: a picture deleted just after it was taken is deleted after it's saved; a cartoon plays, shows an earlier picture, or becomes a video only once everything taken so far can be read back; and leaving the studio lets pictures still being encoded finish before the encoding worker stops. A cartoon in the page's state is a Svelte proxy, which can't be posted to a worker or stored, so what crosses those lines is a snapshot or a copy.

The studio keeps the screen on with a wake lock, stops the camera when the app goes into the background and starts it again when it's back, and remembers on the device which camera was used last. Pictures from a camera that faces the child are mirrored, as the viewfinder shows them. Space or Enter takes a picture unless a button has the focus, as do the volume keys that remote shutters for selfies press where the browser reports them; Backspace deletes, P plays, and G switches the ghost.

## Offline and updates

The service worker (`src/service-worker/index.ts`) keeps the whole site on the device. Installing a version stores every file of the build, every static file, and every prerendered page in a cache named after the build (`version.name` in `vite.config.ts`, the build's time in base 36), bypassing the HTTP cache. The app's pages and the build's files are then answered from this version's cache, else the previous version's, else the network; the privacy page comes from the network, and from the cache without one; a page that isn't stored, without a network, gets the 404 page.

A new version takes over as soon as it's stored (`skipWaiting` and `clients.claim`). The previous version's cache stays until the next version arrives, so an app still running it can load the code it hasn't needed yet. The app moves to the new version on its way back to the cartoons, where nothing is in the middle of being made (`src/routes/(app)/+layout.svelte`), and an app left open for days asks for news whenever it comes back into view. SvelteKit's own polling for new versions is off. The app registers the worker itself, after the page has loaded, as a classic script: it's built as one file without imports, which browsers without module service workers run too. During development there's no service worker.

## Speed

The privacy and app pages score 100 for performance, accessibility, best practices, and SEO in Lighthouse, on mobile and desktop, in both languages. Measure on a production build served as Cloudflare serves it (`npm run build && npm run preview`), not the development server. What keeps it there:

- The privacy page carries no JavaScript.
- Fonts are self-hosted variable fonts, only Latin and Latin Extended, with metric-matched local fallbacks (computed with Capsize), so text doesn't move when they swap in. `src/hooks.server.ts` preloads Baloo 2 everywhere, Hanken Grotesk only on the privacy page, and Latin Extended only on Croatian pages.
- The app's pages show their largest words in the prerendered HTML, and nothing larger appears later: the cartoons' page says what to do under its heading, and the studio shows a bear and the same words, drawn inline, while the camera starts. The largest contentful paint then comes with the first paint, and a camera problem, shown later in smaller type, doesn't move it.
- Nothing heavy loads before it's needed: the encoding worker with the first picture, and Mediabunny, about 60 kB compressed, only with a video.
- Files whose names change with their content are cached for a year (`static/_headers`).

## Design

The look is BubbleBoard's cheerful glass in a younger key: translucent white surfaces over soft sky, pink, mint, and sun gradients on a warm cream canvas, with Baloo 2, a rounded display font, for headings and the app's words, and Hanken Grotesk for text. The studio is a dark room instead, so the camera's picture is the brightest thing on the screen. The logo is BubbleBoard's three bubbles on a sky-to-violet tile, with the big one a red record button.

`src/lib/styles/app.css`, the only stylesheet, holds the theme tokens (`ink`, `muted`, `canvas`, `accent`, the logo's `sky`, `mint`, `sun`, `pink`, and the shutter's `coral`, and the studio's `night` and `dusk`) and the utilities `glass`, `frosted`, `bg-brand`, `text-brand`, and `studio`. Style with Tailwind utilities in markup; component `<style>` blocks hold keyframes and grid areas, which Tailwind can't say well. Palette colours are not automatically text colours: sky, mint, sun, and pink are too light for text on the canvas.

Children use the app before they can read, so its controls are pictures: a red button, a ghost, a turtle and a rabbit, a bin. Every one has a label for screen readers in both languages, and what just happened (a picture taken or deleted) is announced politely. The studio's main buttons are 56 pixels across, those in its top bar 48, and the shutter 96. The settings are the one place with words to read, since they're for grown-ups: radio buttons and switches, built on the browser's own inputs. The studio turns off text selection, long-press callouts, double-tap zoom, and overscroll, so small fingers can't get lost.

Icons come from `src/lib/components/Icon.svelte`, Lucide paths joined into one path each. Use semantic HTML, visible focus, and reduced-motion support. Font, icon, and library licenses are in `static/third-party-notices.txt`, which the site serves; update it when bundling a new asset or library.

## Security

A hash-mode CSP (`csp` in `vite.config.ts`) allows same-origin resources only, plus images and media from the `blob:` URLs the app makes for its own pictures and videos: no inline scripts or styles beyond SvelteKit's hashed ones, no plugins, no framing. Pages carry it as a `<meta>` tag and get the other security headers, including `frame-ancestors`, from `static/_headers`. SvelteKit's route announcer has one fixed inline style attribute, which `style-src-attr` allows by hash (`'unsafe-hashes'`, never `'unsafe-inline'`); `src/csp.test.ts` fails when a SvelteKit update changes it. Dynamic sizes are set through the CSSOM (Svelte's `style:` directives, in the browser only), which the CSP doesn't restrict; the prerendered HTML has no `style` attributes, which is why the studio follows the settings only once it runs in the browser (`Studio.configure`). `Permissions-Policy` allows the camera and the microphone to this site only, and nothing else.

## Dependency policy

Use platform APIs and Svelte first. Add a library only for an implemented need, after checking maintenance, licensing, bundle cost, and transitive dependencies. Mediabunny (MPL-2.0, no dependencies) writes video files; writing MP4 by hand is possible but easy to get subtly wrong for some player, and the video must play everywhere a family sends it. Vitest runs the tests, with `fake-indexeddb` giving the storage tests a real store in Node. No component UI library, global state package, analytics, remote fonts, or remote images.

On 2026-11-02, `npm audit` reported a low-severity advisory in `deepmerge`, which `@sveltejs/vite-plugin-svelte` uses to merge its configuration at build time; nothing of it reaches the site. Recheck when updating the toolchain.
